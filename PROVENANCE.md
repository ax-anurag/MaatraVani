## Models (all local after one-time download)

| role | model | source repository | approx. size | license |
|------|-------|-------------------|--------------|---------|
| translation | NLLB-200-distilled-600M, converted to CTranslate2 int8 | weights: [facebook/nllb-200-distilled-600M](https://huggingface.co/facebook/nllb-200-distilled-600M); conversion performed locally by `scripts/download_models.py` (`ct2-transformers-converter`) | ~2.5 GB fp32 in, ~0.7 GB int8 out | CC-BY-NC-4.0 (see note) |
| ASR (fast) | Vosk small Hindi 0.22 | [alphacephei.com/vosk](https://alphacephei.com/vosk/models) | ~45 MB | Apache-2.0 |
| ASR (accurate) | faster-whisper small (int8) | [Systran/faster-whisper-small](https://huggingface.co/Systran/faster-whisper-small) | ~460 MB | MIT (model weights MIT, per OpenAI Whisper) |
| TTS (Hindi) | espeak-ng `hi` voice | [github.com/espeak-ng/espeak-ng](https://github.com/espeak-ng/espeak-ng) | ~4 MB | GPLv3 |
| TTS (Santali) | espeak-ng `hi` voice reading Ol Chiki → Devanagari transliteration (`backend/engines/tts/sat_translit.py`, team-authored mapping) | letter values from the public Ol Chiki letter inventory (Ol Chiki Unicode block / Wikipedia table); espeak-ng engine itself GPLv3 | ~100 lines of Python | team-authored mapping, same license as the repo |

**NLLB license note:** the distilled NLLB weights are CC-BY-NC-4.0 —
fine for a hackathon/education prototype, **non-commercial**. A production
deployment must re-license or swap the translation engine; the
`TranslationEngine` abstraction exists precisely so that swap is local.

**Conversion history:** this PoC originally used the prebuilt CTranslate2
conversion `michaelfeil/ct2fast-nllb-200-distilled-600M`. That repository
became unreachable on the Hub (401 for anonymous access, 2026-09-25), so
`scripts/download_models.py` now downloads the official Facebook weights
and runs the int8 conversion locally, in a one-time throwaway venv
(`.venv-convert`, needed because the converter's `transformers`
dependency conflicts with the app venv's `tokenizers` pin). The script
still tries the prebuilt first, in case it returns.

**Choice rationale (short version; full reasoning in README):**
NLLB-200 is the only open offline MT with Santali coverage at all —
IndicTrans2 has no Santali. Vosk-small-hi is ~45 MB and sub-second on a
CPU. For Santali TTS there is NO offline voice anywhere — upstream
espeak-ng has no `sat` voice (verified against `dictsource/` on master,
2026-09-25) — so Santali audio goes through a team-authored Ol Chiki →
Devanagari transliteration read by the espeak-ng Hindi voice. Ol Chiki is
a phonemic alphabet, so the reading is robotic (Hindi phonology) but the
actual Santali text, offline; the UI labels it as such and never
substitutes other-language audio.

**Translation honesty note:** NLLB-200's only Santali language code is
`sat_Beng` (Bengali script — no Ol Chiki code exists in the model's
vocabulary), and our locally converted distilled-600M int8 build emitted
unrelated languages for `sat_Beng` targets. The composite engine therefore
serves the demo through the verified lexicon (exact phrase matches) and a
word-by-word gloss of verified words, labelled partial; NLLB output is
used only when it actually lands in the target script.

## Datasets

| dataset | file | what it is | license/origin |
|---------|------|------------|-----------------|
| verified classroom lexicon | `content/vocabulary/lexicon.json` | small Hindi–Santali vocabulary; every entry records its own `source` field plus the sources its bytes were checked against (`verified_against`) | entries verified by the team against public sources; the machine-extracted token sets we checked against are checked in at `content/vocabulary/evidence.json` (regenerated by `scripts/collect_lexicon_evidence.py`, enforced by `tests/test_lexicon_evidence.py`). No machine translation is ever written into this file |
| FLN outcome catalog | `content/lessons/fln_outcomes.json` | representative, reworded subset of NIPUN Bharat foundational-literacy/numeracy outcomes, assembled for this PoC | written by the team; **not** an official copy of the Lakshya documents |
| demo sentences | `content/demo/demo_sentences.json` | the 7 fixed Hindi utterances used in the demo, tests and latency measurements | written by the team |

All three are generated from the Python literals in `content/seed.py`
via `scripts/emit_content.py`, so the seed is reviewable in one place.

## APIs

| API | what it does | when it is used |
|-----|--------------|-----------------|
| Bhashini / ULCA pipeline (`api.bhashini.cg.gov.in`) | optional online ASR/MT/TTS | **never by default**; requires credentials in `.env` (see `.env.example`), auto-disabled in offline mode, throttled by the same 25-req/min budget. Not exercised in our demo — we had no credentials — and labelled experimental in code and UI |

No other external API is called anywhere. Model download
(`scripts/download_models.py`) is the only component that needs the
network, and only once.

## What the team implemented

* the entire voice pipeline orchestration, stage-failure semantics and
  per-stage latency measurement (`backend/services/pipeline.py`)
* the lexicon-first composite translation strategy with provenance on
  every line (`backend/engines/translation/`)
* the template-driven bilingual lesson generator around FLN outcomes,
  the worksheet PDF with dual-script shaping, flashcard SVG/PDF renderers
* the mesh message format, TTL/duplicate rules, the deterministic
  classroom simulation, and the BLE transport behind the same interface
* the 25-req/min sliding-window limiter (API middleware + outbound throttle)
* the offline verification harness (`scripts/offline_demo.py`,
  `tests/test_offline.py`) that crashes on any network attempt
* the whole frontend (vanilla ES modules, client-side WAV encoding,
  WebSocket event timeline)

## What is NOT ours (and how we verified what we ship)

* the four models, the fonts and the libraries above — see tables
* Santali vocabulary in the lexicon: only entries whose `source` field
  names a checkable public source. The sources actually used: the
  Omniglot and countbylanguage number lists, Wikibooks "Santali/Animals",
  sat.wikipedia article titles (via Wikidata sitelinks) and sat.wiktionary
  entries. The exact bytes we checked each entry against are
  machine-extracted into `content/vocabulary/evidence.json` and enforced
  by `tests/test_lexicon_evidence.py`. The autonym shown in the UI is copied
  programmatically from the project brief, never re-typed —
  `scripts/sync_autonym.py` and `tests/test_script_integrity.py` enforce
  this repo-wide, because hand-retyping Ol Chiki is exactly how a
  neighbouring-script character sneaks in.
